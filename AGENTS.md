# Portfolio website

## UI design

- Always use [Apple’s Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) when designing, implementing, or reviewing UI in this repository. Consult the relevant sections, including [Typography](https://developer.apple.com/design/human-interface-guidelines/typography), [Layout](https://developer.apple.com/design/human-interface-guidelines/layout), and [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility).
- Apply the guidance to the web. Use consistent roles for titles, headings, body text, controls, and captions. Use scalable text sizes, preserve the hierarchy when text is enlarged, and check narrow layouts and touch targets in the browser.

## Project writeups

- Use concise, factual prose in the style of a textbook or technical document. Start with a plain-language explanation of what the project is and what it does. Then explain its documented behavior and show a whole-system architecture diagram covering inputs, main components, interfaces, and outputs. Use [arc42](https://arc42.org/overview/) and the [C4 model](https://c4model.com/introduction) as references.
- Verify technical details against the project repositories. Label illustrative data and ask for context when a material detail cannot be inferred from the sources.
